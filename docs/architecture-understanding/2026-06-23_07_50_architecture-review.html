02Coupling Analysis

Root-Zero-Import Invariant: VERIFIED

Root (package output) imports ZERO sub-modules in production code. Only testhelpers (zero-dep, independently versioned) appears in root's go.mod. This is the load-bearing architectural guarantee — go get github.com/larsartmann/go-output pulls NO lipgloss, NO bubbletea, NO yaml/toml deps.

Registry Dispatch via init() Pattern: EXCELLENT

Root's RenderTableData() / RenderAnyData() dispatch to registered marshalers, yet root imports no sub-module. Each sub-module calls RegisterFormatShapes() in its own init(). Importing a sub-module activates it. This is textbook dependency inversion.

Composition via GraphRendererState: EXCELLENT

DOT/Mermaid/PlantUML renderers embed root's GraphRendererState for shared state via AddNode/AddEdge. AddTreeNodes accepts the NodeEdgeAppender interface, not a raw slice pointer. Composition over inheritance done right.

Pattern B Migration: INCOMPLETE

The AGENTS.md states "ALL inter-module sibling deps use v0.0.0-00010101000000-000000000000" but the reality is that 165 of 177 sibling requires use real published versions (v0.17.x). Only bdd/ and integration/ partially use the sentinel. examples/go.mod uses zero sentinels — all 11 deps at v0.17.2.

Impact: go mod tidy may update sibling versions when new tags are published, re-introducing the version-rot problem Pattern B was designed to eliminate.

Fix: Run go mod edit -require=github.com/larsartmann/go-output@v0.0.0-00010101000000-000000000000 in each module, then go mod tidy. See TODO_LIST.md #17.
