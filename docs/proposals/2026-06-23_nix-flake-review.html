Multi-Module Architecture

runForModules pattern — elegant multi-module support

The flake defines a runForModules helper that iterates all 18 modules, cds into each, and runs the specified Go command. This avoids the complexity of buildGoModule per module and leverages the workspace's replace directives. GOWORK = "off" in devShells ensures flake apps work consistently (go.work is gitignored, generated on demand).

Intentional design: Go checks not in nix flake check

Sandbox blocks go mod download, so Go build/test/lint checks are NOT in nix flake check. They run as Nix apps (nix run .#build, nix run .#test, nix run .#lint) and in CI workflows. This is a deliberate design decision documented in AGENTS.md.

Verdict

The flake.nix is exemplary. It follows the ecosystem standard stack perfectly, handles the multi-module Go workspace elegantly, and correctly avoids putting Go checks in the sandbox. No changes needed.
