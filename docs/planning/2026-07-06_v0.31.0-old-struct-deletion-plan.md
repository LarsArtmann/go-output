# v0.31.0 Decision Record — Old Renderer Struct Deletion

**Date:** 2026-07-06
**Status:** DRAFT — awaiting v0.30.0 release
**Prerequisite:** v0.30.0 tagged and shipped

---

## Context

v0.30.0 introduced CQRS pure-function renderers alongside the existing mutable renderer structs. The structs remain as implementation detail backing the CQRS functions. This creates a split brain:

- `graph.RenderDOT(g)` — CQRS pure function (recommended)
- `graph.NewDOTRenderer().Render()` — old struct (still works, produces same output for DOT)
- `serialization.WriteJSON(w, data)` — CQRS streaming (produces trailing `\n`)
- `serialization.NewJSONTableRenderer().Render()` — old struct (produces NO trailing `\n`)

The registry dispatch was rewired to call CQRS functions directly. The old structs are no longer the dispatch path but remain part of the public API.

## Audit Results (2026-07-06)

| `JSONTableRenderer` |              No — registry calls `WriteJSON` directly              |                         `serialization/json.go` (`Render()` method)                         |
| `YAMLTableRenderer` |              No — registry calls `WriteYAML` directly              |                         `serialization/yaml.go` (`Render()` method)                         |
| `TOMLTableRenderer` |              No — registry calls `WriteTOML` directly              |                         `serialization/toml.go` (`Render()` method)                         |
| `ASCIITreeRenderer` | **Yes** — `WriteASCII` creates `NewASCIITreeRenderer()` internally |               `examples/`, `tree/tree.go` (registry), `TreeRendererFromTable`               |

### Downstream Callers

Only known consumer: `BuildFlow/execution` (uses `go-output v0.23.3`). Does NOT call any old renderer structs directly — uses only `nom/` and `tui/` modules.

## Decision

**Delete in v0.31.0 in three phases:**

### Phase 1: Inline CQRS functions (remove struct dependency)

For structs that CQRS functions call internally (MermaidRenderer, ASCIITreeRenderer, MarkdownTable, PlantUMLDiagram), extract the rendering logic into shared free functions (same pattern as DOT's `renderDOTString`). CQRS functions call the free functions directly. Old structs delegate to the same free functions.

### Phase 2: Delete old structs + constructors

Remove: `DOTRenderer`, `MermaidRenderer`, `JSONTableRenderer`, `YAMLTableRenderer`, `TOMLTableRenderer`, `ASCIITreeRenderer`, `MarkdownTable`, `PlantUMLDiagram`.

Remove constructors: `NewDOTRenderer`, `NewMermaidRenderer`, `NewJSONTableRenderer`, `NewYAMLTableRenderer`, `NewTOMLTableRenderer`, `NewASCIITreeRenderer`, `NewMarkdownTable`, `NewPlantUMLDiagram`.

Remove converters: `NewDOTFromTable`, `NewDOTFromTree`, `NewMermaidFromTable`, `NewMermaidFromTree`, `NewPlantUMLFromTable`, `NewPlantUMLFromTree`, `TreeRendererFromTable`.

Remove helpers: `renderTable` (serialization), `renderMarshalAndWrite` (markup, if AsciiDoc also rewired).

### Phase 3: Migrate examples + integration tests

Update `examples/basic/renderers.go`, `examples/diagram_export/main.go`, `integration/test_helpers.go` to use CQRS functions only.

## Migration for Consumers

```go
// Old (v0.30.0)
r := graph.NewDOTFromTable(data)
out, _ := r.Render()

// New (v0.31.0)
g := output.TableToGraph(data)
out, _ := graph.RenderDOT(g)
```

```go
// Old
r := tree.NewASCIITreeRenderer()
r.SetRoot(rootNode)
out, _ := r.Render()

// New
out, _ := tree.RenderASCII(rootNode)
```
