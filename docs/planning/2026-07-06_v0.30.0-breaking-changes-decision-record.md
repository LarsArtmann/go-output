## Appendix A: CQRS Architecture Vision (v0.30.0)

### The Principle

> **A Renderer renders. It does not mutate. If it has state, it's a Builder, not a Renderer.**

Today every renderer is a god object — it's simultaneously a data store (mutable state) AND a renderer (string output). This mixes the write side and the read side in one type. Kotlin gets this right with `List` vs `MutableList` — the read side is a frozen interface, the write side is a separate type.

### Current Problem

```go
// DOTRenderer is BOTH a mutable data store AND a renderer.
type DOTRenderer struct {
    nodes []GraphNode     // ← state (write side)
    edges []GraphEdge     // ← state (write side)
    direction Direction   // ← config (write side)
}

func (d *DOTRenderer) AddNode(node)     // ← COMMAND (mutate)
func (d *DOTRenderer) AddEdge(edge)     // ← COMMAND (mutate)
func (d *DOTRenderer) Render() string   // ← QUERY (read + side effect)
```

Problems:

- Can't render same graph in two formats without building twice or sharing mutable state
- Concurrent rendering requires locks
- Can't cache — mutable objects can't be safely cached
- Testing requires construct → mutate → assert (not table-driven)
- Violates CQRS: render and mutate are entangled

### CQRS Solution: Write Side (Builders)

```go
// ──────────────────────────────────────────────
// GRAPH
// ──────────────────────────────────────────────
b := output.NewGraphBuilder()
b.AddNode(output.GraphNode{ID: "compile", Label: "Compile"})
b.AddNode(output.GraphNode{ID: "test", Label: "Test"})
b.AddEdge(output.GraphEdge{From: "compile", To: "test"})
b.SetDirection(output.DirectionDown)

g := b.Build() // → Graph (immutable, frozen)

// ──────────────────────────────────────────────
// TABLE
// ──────────────────────────────────────────────
b := output.NewTableBuilder()
b.SetHeaders("Name", "Status", "Duration")
b.AddRow("Compile", "✓", "2.1s")
b.AddRow("Test", "✓", "5.3s")
b.SetFooter("Total", "", "7.4s")

t := b.Build() // → Table (immutable, frozen)

// ──────────────────────────────────────────────
// TREE
// ──────────────────────────────────────────────
b := output.NewTreeBuilder()
b.SetRoot(output.TreeNode{ID: "build", Label: "Build"})
b.AddChild("build", output.TreeNode{ID: "compile", Label: "Compile"})
b.AddChild("build", output.TreeNode{ID: "lint", Label: "Lint"})

tr := b.Build() // → Tree (immutable, frozen)
```

### CQRS Solution: Freeze Boundary

`Build()` returns an **immutable value type**. No exported setters. No mutation methods. Copy-by-value is safe.

```go
// Graph is a frozen snapshot of a graph builder's state.
type Graph struct {
    nodes     []GraphNode    // sorted, frozen
    edges     []GraphEdge    // sorted, frozen
    direction Direction      // frozen
}

type Table struct {
    headers []string         // frozen
    rows    [][]string       // frozen
    footer  []string         // frozen
}

type Tree struct {
    root  *TreeNode          // frozen tree
    nodes []TreeNode         // flattened, frozen
}
```

After `Build()`:

- Pass the same `Graph` to DOT, Mermaid, D2, and PlantUML — zero risk
- Share it across goroutines — no locks
- Cache it — it never changes

### CQRS Solution: Read Side (Pure Function Renderers)

Every renderer is a **package-level function**, not a method on a mutable struct.
Following Go convention (`fmt.Fprintf`/`fmt.Sprintf`, `json.Encode`/`json.Marshal`),
the primary API writes to `io.Writer`; the convenience wrapper returns a string:

```go
// ──────────────────────────────────────────────
// GRAPH RENDERERS — Write (primary) + Render (convenience)
// ──────────────────────────────────────────────
var buf strings.Builder
_ = graph.WriteDOT(&buf, g, graph.WithDirection(output.DirectionDown))
dot := buf.String()

// Convenience: returns string directly
dot,     _ := graph.RenderDOT(g)      // wraps WriteDOT into strings.Builder
mermaid, _ := graph.RenderMermaid(g)
d2Out,   _ := d2.Render(g)
puml,    _ := plantuml.Render(g)

// ──────────────────────────────────────────────
// TABLE RENDERERS
// ──────────────────────────────────────────────
_ = delimited.WriteCSV(w, t)                    // streaming to any io.Writer
csv,  _ := delimited.RenderCSV(t)               // convenience → string
tsv,  _ := delimited.RenderTSV(t)
json, _ := serialization.RenderJSON(t)
yaml, _ := serialization.RenderYAML(t)
toml, _ := serialization.RenderTOML(t)
jsonl,_ := serialization.RenderJSONL(t)
xml,  _ := markup.RenderXML(t)
html, _ := markup.RenderHTML(t)
adoc, _ := markup.RenderAsciiDoc(t)
md,   _ := markdown.Render(t)
tbl,  _ := table.Render(t, table.WithColorMode(output.ColorModeAuto))

// ──────────────────────────────────────────────
// TREE RENDERERS
// ──────────────────────────────────────────────
ascii, _ := tree.RenderASCII(tr)
md,     _ := tree.RenderMarkdown(tr)

// ──────────────────────────────────────────────
// CROSS-SHAPE CONVERSIONS (pure projections)
// ──────────────────────────────────────────────
g := output.TableToGraph(t)  // Table → Graph
tr := output.GraphToTree(g)  // Graph → Tree
t := output.GraphToTable(g)  // Graph → Table
```

**Naming convention:** `WriteXxx(w, model, opts...) error` is primary (streaming);
`RenderXxx(model, opts...) (string, error)` is the convenience wrapper. Every `RenderXxx`
is a 3-line function: `var b strings.Builder; err := WriteXxx(&b, model, opts...); return b.String(), err`.

### What Dies (CQRS)

Every mutable renderer struct:

| Deleted (mutable renderer)                    | Replaced By                            |
| --------------------------------------------- | -------------------------------------- |
| `DOTRenderer` (AddNode, SetDirection, Render) | `graph.RenderDOT(g)`                   |
| `MermaidRenderer`                             | `graph.RenderMermaid(g)`               |
| `D2Diagram` (AddNode, SetDirection, Render)   | `d2.Render(g)`                         |
| `PlantUMLDiagram`                             | `plantuml.Render(g)`                   |
| `ASCIITreeRenderer` (SetRoot, Render)         | `tree.RenderASCII(tr)`                 |
| `MarkdownTable` (SetColorMode, Render)        | `markdown.Render(t, opts)`             |
| `GraphRendererState` (the mixin)              | `GraphBuilder` (write side only)       |
| `TableDataStore`                              | `TableBuilder`                         |
| `StreamingRendererFromRenderer`               | Gone — streaming is a separate concern |

### What Stays (CQRS)

**Registry dispatch** — query-side router, not a mutable renderer:

```go
output.RegisterFormat(output.FormatCSV, delimited.RenderCSV)
output.RegisterFormat(output.FormatJSON, serialization.RenderJSON)

out, _ := output.Render(t, output.FormatJSON)
```

**nom/ package** — already CQRS:

```go
// Command side: events
sub.OnEvent(ctx, nom.ActivityStarted{...})

// Query side: immutable snapshots
snaps := sub.SnapshotActivities()
frame := tree.RenderWithSnapshots(snaps, 20, 80)
```

The nom subscriber IS the builder. Snapshots ARE the freeze. `RenderWithSnapshots` IS a pure function. nom/ is the reference implementation for the pattern.

### The Big Picture

```
WRITE SIDE                   FREEZE              READ SIDE
─────────                    ──────              ─────────
GraphBuilder.Build()    →    Graph          →    RenderDOT(g)
                                                RenderMermaid(g)
                                                RenderD2(g)
                                                RenderPlantUML(g)

TableBuilder.Build()    →    Table          →    RenderCSV(t)
                                                RenderJSON(t)
                                                RenderYAML(t)
                                                RenderHTML(t)
                                                RenderMarkdown(t)
                                                ...12 renderers

TreeBuilder.Build()     →    Tree           →    RenderASCII(tr)
                                                RenderMarkdown(tr)

NOMSubscriber.OnEvent() →    Snapshots      →    RenderWithSnapshots(snaps)
                             (already CQRS)      (already pure)
```

**Every arrow left-to-right is one-way.** The read side can never mutate. The write side can never render. The freeze is the only bridge.

### What CQRS Unlocks

| Capability                    | Today (mutable renderer)           | CQRS (immutable model)                          |
| ----------------------------- | ---------------------------------- | ----------------------------------------------- |
| Render same data in 2 formats | Build twice or share mutable state | `RenderDOT(g)` + `RenderMermaid(g)` — zero risk |
| Concurrent rendering          | Lock the renderer (or race)        | Immutable = no locks. Ever.                     |
| Caching                       | Can't cache a mutable object       | Cache `Graph` by value. Deterministic.          |
| Testing                       | Construct → mutate → assert        | `Render(testGraph)` — table-driven              |
| Renderer with bug             | State + render tangled             | Pure function — isolate the bug                 |
| Mental model                  | "Renderer that accumulates"        | "Build, freeze, render" — one direction         |
| nom/ alignment                | nom/ is CQRS, rest isn't           | **All modules are CQRS**                        |

## Appendix B: Additional v0.30.0 Decisions (D1-D10)

These decisions supplement the CQRS architecture (Appendix A) and the rename/deletion
plan (Sections B-C). All resolved — no open questions.

### D1: Primary API — `io.Writer` primary, `string` convenience

**Decision:** Every renderer exports two functions:

```go
// Primary — streams to any io.Writer
func WriteDOT(w io.Writer, g Graph, opts ...Option) error

// Convenience — returns string (3-line wrapper around Write)
func RenderDOT(g Graph, opts ...Option) (string, error)
```

**Rationale:** Go convention. `fmt.Fprintf`/`fmt.Sprintf`, `json.Encode`/`json.Marshal`,
`template.Execute`/`template.ExecuteTemplate`. Writer-primary gives streaming for free;
the string wrapper costs 3 lines and zero ergonomics loss. The current split brain
(`Renderer.Render() (string, error)` vs `TableDataRenderer func(w, ...) error`) is
resolved: every renderer follows ONE convention.

### D2: Functional Options Everywhere

**Decision:** Every renderer accepts `opts ...Option` using the functional-options pattern.

```go
graph.WriteDOT(w, g, graph.WithDirection(output.DirectionDown))
table.Render(t, table.WithColorMode(output.ColorModeAuto))
d2.Write(w, g, d2.WithSketchMode())
```

**Rationale:** Already used in `nom/`, `table/`, and `daghtml/`. Extending to all
renderers gives a uniform, extensible API. Adding new options in v1.1 doesn't break
consumers (variadic). No more rigid `RenderOptions` struct.

**Each renderer module exports its own `Option` type and `With*` functions.** Shared
options (like `ColorMode`) are defined in root and re-exported or wrapped by modules.

### D3: Minimum Go Version — `go 1.26`

**Decision:** All 19 modules declare `go 1.26` in go.mod.

**Rationale:** Already the de facto minimum. Go 1.26 provides generics, range-over-func,
and all language features the codebase uses. Documented in README and AGENTS.md.

### D4: `testhelpers/` Tags v0.30.0

**Decision:** `testhelpers/` tags v0.30.0 alongside root. It is the only other independently
consumable module (zero-dep, real published versions).

**Rationale:** Consumers' test suites depend on it. v0.30.0 signals "stable for your tests too."

### D5: Stability Tiers ADR

**Decision:** New ADR `docs/adr/0011-api-stability-tiers.md` documents which APIs are frozen
vs experimental.

| API Surface                                                    | Tier                          | Rationale                     |
| -------------------------------------------------------------- | ----------------------------- | ----------------------------- |
| Root model types (`Table`, `Graph`, `Tree`, `GraphNode`, etc.) | **Frozen**                    | Core data model               |
| Builder API (`NewGraphBuilder`, `AddNode`, `Build()`)          | **Frozen**                    | Write-side contract           |
| Render functions (`RenderDOT`, `WriteCSV`, etc.)               | **Frozen**                    | Read-side contract            |
| Registry dispatch (`RegisterFormat`, `Render`)                 | **Frozen**                    | Extensibility contract        |
| nom/ events + subscriber                                       | **Frozen**                    | Command-side contract         |
| nom/ snapshot model                                            | **Frozen**                    | Query-side contract           |
| nom/ themes                                                    | **Experimental**              | New v0.23 feature, may evolve |
| daghtml/                                                       | **Experimental**              | New module, still maturing    |
| Functional option names per module                             | **Frozen** once v0.30.0 ships |                               |

### D6: Registry Panics on Duplicate Registration

**Decision:** `RegisterFormat()` panics if a format is already registered.

**Rationale:** Double-registration is a programming error (double-import). Silent
last-writer-wins is a debugging nightmare — the wrong renderer wins with no signal.

### D7: Merge `escape/` Into Root

**Decision:** Merge `escape/` module into root `package output`. All escaping functions
move to `root/escape.go` (or similar). The `escape/` go.mod is deleted.

**Rationale (from go-modularize skill, FM#8):** The `escape/` module has zero
composability payoff as a separate module. No consumer imports `escape/` without
also importing root. Every renderer module imports it. The module boundary adds a
go.mod with zero value. Decomposition depth is correct (single-purpose package), but
the MODULE boundary is too fine — it should be a package, not a module.

**Module count after merge:** 18 (down from 19).

**All other modules stay.** go-modularize evidence:

- Each renderer module (graph/, d2/, plantuml/, tree/, table/, etc.) has clear
  single-purpose scope and is independently importable.
- Co-change is driven by shared dependency (root types), not real coupling.
- `delimited/`, `serialization/`, `markup/` share only a cross-cutting concern
  (format rendering) — not evidence to merge.
- `nom/` and `tui/` have genuine independent composability (progress visualization
  vs interactive TUI).

### D8: Benchmark Baselines

**Decision:** Add `benchmark_test.go` to each renderer module with a baseline benchmark.

- Graph renderers: 100 nodes, 150 edges
- Table renderers: 100 rows, 5 columns
- Tree renderers: 100 nodes, depth 5

v0.30.0 ships with performance baselines so v1.1 regressions are detectable.

### D9: Godoc Examples

**Decision:** Add at least one `Example()` function per renderer module. These appear in
pkg.go.dev/godoc and are tested by `go test`. Critical for v0.30.0 discoverability.

Currently only `nom/` has runnable examples. Every module should have one.
