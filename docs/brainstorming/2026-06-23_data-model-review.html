Overall Grade

The type system is remarkably well-designed for a library of this scope. Branded phantom types prevent ID-mixing at compile time, a sealed Event sum type makes non-exhaustive switches compile errors, and generic registries eliminate boilerplate. The problems found are minor inconsistencies, not structural flaws.

Strengths — What the Type System Gets Right

Pattern Where Why It Matters
Branded phantom types BrandedID[T], GraphNodeID, TreeNodeID, D2NodeID Compile-time prevention of ID-type mixing. You cannot pass a TreeNodeID where a GraphNodeID is expected.
Sealed Event sum type nom.Event interface with unexported isEvent() Only the 7 structs in event.go can implement Event. Adding a new event makes every non-exhaustive switch a compile error. No string dispatch.
Generic format registry formatRegistry[T] One implementation backs shape capabilities, tableData, and anyData registries. Zero code duplication.
Generic enum utilities ParseEnum[T](), ContainsEnum[T]() All enums share parse/validate logic via generics. No boilerplate per enum.
Immutable snapshot model ActivitySnapshot Mutable Activity fields consumed via immutable value copies under read lock. Eliminates the data race the old shared-pointer model caused.
O(1) count cache ActivityCounts struct Incrementally maintained via applyCountsDelta on every transition. GetActivityCounts() never scans the activity map.
Composition via GraphRendererState DOT/Mermaid/PlantUML embed GraphRendererState Shared node/edge state via embedding without inheritance. AddTreeNodes accepts an interface, not a raw slice pointer.
Named types over string ActivityID, ActivityName, WorkflowID Named string types with constructors + String()/IsZero(). Prevents accidentally passing a workflow name as an activity ID.

Problem Catalog

P1: RowEdge uses raw string instead of branded GraphNodeID

Severity: Medium · tabledata.go:174-178

RowEdge.From and RowEdge.To are raw string while the rest of the graph type system uses branded GraphNodeID. AddRowEdges immediately re-wraps them in NewBrandedID. The type boundary is unenforced — a caller could pass arbitrary strings.

Fix: Change RowEdge to use GraphNodeID fields. Internal-only type, so no breaking change.

P2: NodeShapeBox and NodeShapeRect are semantic duplicates

Severity: Low · graph.go:45,52

Two exported names for the same visual concept. Every renderer treats them identically (d2_convert.go:70, mermaid.go:119). This is a split-brain: two names, one meaning.

Fix: Deprecate NodeShapeRect and alias to NodeShapeBox. Can't remove pre-v1 (ADR 006 stability).

P3: LineStyle enum is incomplete

Severity: Low · graph.go:67-89

Has IsValid() but no ParseLineStyle, AllowedValues(), or InvalidLineStyleError. Inconsistent with Format/Shape/ColorMode/NodeShape which all have the full set.

P4: Direction enum lacked validation (FIXED)

Severity: Medium · direction.go

Fixed this session: Added AllDirections and IsValid() method. Direction now has the same validation surface as other enums.

P5: InvalidShapeError omitted Allowed field (FIXED)

Severity: Low · shape.go:42-59

Fixed this session: Added Allowed []Shape field matching InvalidFormatError. Error message now lists valid options.

The Vision — Where the Type System Could Go

Goal: Zero raw-string type boundaries

Every ID flowing through the public API should be branded. The only remaining gap is RowEdge (P1). Fixing it would complete the branded-ID perimeter.

Goal: Complete enum parity

Every enum should have the full set: constants, All* slice, IsValid(), Parse*(), AllowedValues(), typed error. LineStyle (P3) is the last incomplete one. Direction (P4) was fixed.
