## E) WHAT WE SHOULD IMPROVE

### Architecture

1. **RenderTableData dispatch inconsistency** — Markdown and Tree use direct `switch` dispatch while sub-modules register via `init()`. Should unify: markdown/tree register as marshalers too, eliminating the switch entirely in `RenderTableData()`. This makes the architecture symmetric.

2. **Registry callbacks lack test coverage** — The `render*TableData()` functions registered via `init()` in sub-modules are at 0% coverage because they're only invoked through `RenderTableData()` in root, and integration tests go through direct constructors instead. Need integration test paths that exercise `RenderTableData()` for every registered format.

3. **Branded IDs verbosity** — Creating nodes still requires `output.NewBrandedID[output.GraphNodeIDBrand]("id")`. The `NewGraphNode("id", "label")` helper exists but the PlantUML example doesn't use it. Should audit examples to use helpers consistently.

### Code Quality

4. **File size violations** — `integration/integration_test.go` at 457 lines (30% over 350 limit). Should split by format category or extract shared helpers.

5. **testhelpers coverage at 43.5%** — Some exported assertion helpers aren't tested. Low risk but below the 90% target.

6. **Root go.mod has unnecessary direct deps** — `go-faster/yaml` and `serialization` are direct deps but only used by `_test.go` files. Root production code has zero yaml imports. Should investigate if these can be test-only.

### Documentation

7. **ADR 003 is missing PlantUML** — ADR 003 covers d2/graph extraction. PlantUML is a new module without an ADR.

8. **CHANGELOG has two "feat" commits for the same work** — `9545a50` and `b07b426` are both "add JSONL, AsciiDoc, TOML, PlantUML" because the pre-commit hook auto-committed between them. Not harmful but messy.
