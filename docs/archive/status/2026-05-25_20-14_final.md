## Top Question

**Why does `go mod tidy` in workspace mode keep `go-faster/yaml` in root's direct `require` block?**

Answer: Because root's test files (`userjourney_test.go`) import `serialization`, which imports `yaml`. Go treats test dependencies as direct deps. The yaml dep will _not_ be pulled for consumers who `go get github.com/larsartmann/go-output` without importing serialization — Go modules only resolve transitive deps actually needed by imported packages. The LSP warnings are workspace-mode artifacts, not real errors.
