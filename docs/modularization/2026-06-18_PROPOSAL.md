# Re-Modularization Proposal — 2026-06-18

## Executive Summary

Audit of the existing 18-module Go workspace revealed three actionable issues:

1. **Core invariant violation** — root imports `enum` and `envdetect` in production code, contradicting the "zero sub-module imports" rule. These (plus `escape`) should merge INTO root.
2. **Version drift** — 4 modules pin `testhelpers/graphtest` at `v0.6.3`; `integration` pins 5 modules at `v0.6.3`; `tui` is at the zero-placeholder (never tagged).
3. **go.work + replace redundancy** — both strategies coexist for the same module pairs (Failure Mode #4). Replace directives are noise for external consumers; go.work is the correct local-dev tool.

**Result after execution:** 18 modules → 15. Core invariant restored. ~15 replace directives eliminated. Version drift fixed.

## Proposed Changes

### MERGE into root (3 modules → root packages)

| Module       | Files | Why merge                                                                                        |
| ------------ | ----- | ------------------------------------------------------------------------------------------------ |
| `enum/`      | 3     | Root already imports it in 4 production files. Zero-dep. Every consumer already depends on root. |
| `envdetect/` | 2     | Root already imports it in `color.go`. Zero-dep. Every consumer already depends on root.         |
| `escape/`    | 3     | Zero-dep. Used only by d2/graph/markup/plantuml — all already depend on root.                    |

**Import paths do NOT change.** `import "github.com/larsartmann/go-output/enum"` resolves identically whether enum is a separate module or a package within root. Consumers who `go get go-output@vX.Y.Z` get enum/envdetect/escape packages included. **Not a breaking change.**

### KEEP (15 modules)

root (now includes enum/envdetect/escape packages), delimited, d2, graph, markup, plantuml, serialization, table, nom, tui, testhelpers, testhelpers/graphtest, bdd, integration, examples.

### FIX

1. Add missing root require to `graphtest/go.mod`
2. Align all sibling requires to `v0.12.0`
3. Remove stale `internal/` references from AGENTS.md
4. Update `go.work.example` and `flake.nix` (remove 3 merged modules)

### DEFER (needs user decision)

- **Remove replace directives + commit go.work** — correct for published libraries but changes dev workflow. Replace directives are currently the fallback when go.work is absent (gitignored). Removing them requires committing go.work or always running `setup-workspace`.
- **Tag tui at next release** — release action, not code change.

## Migration Strategy (Ordered)

### Tier 1 — Core (foundational, do first)

1. **Merge enum into root** — remove `enum/go.mod`, remove enum from all `replace`/`require` blocks, run `go mod tidy` per module, verify build.
2. **Merge envdetect into root** — same process.
3. **Merge escape into root** — same process.

### Tier 2 — Untangle

4. **Fix graphtest missing require** — add root require to `graphtest/go.mod`.
5. **Fix version drift** — align all sibling requires to `v0.12.0`.

### Tier 3 — Polish

6. **Update go.work.example** — remove enum/envdetect/escape from `use (...)`.
7. **Update flake.nix** — remove enum/envdetect/escape from `modules` list.
8. **Update AGENTS.md** — fix module count (18→15), remove stale `internal/` refs, update module map.

### Verification (after each step)

```bash
go build ./...                    # workspace build
cd <module> && GOWORK=off go build ./...  # isolated build
go test ./...                     # workspace tests
```

## Not Executed (Proposed for Future)

- **Remove replace directives** — The correct strategy for a published multi-module library is versioned requires + committed go.work (no replace directives). Currently deferred because it changes the dev workflow (go.work is gitignored; removing replace requires committing go.work). Recommend a follow-up with user buy-in.
