06Recurring Patterns

6 instances

"Tests encode the bug" — expectations derived from the same constant/formula as the implementation

table footer index · tui click formula · nom counts recount helper · PlantUML golden · buildStyleFunc footerRowIndex · XML vacuous guard

When a test computes its expectation from the implementation's own field or regenerates its golden from buggy output, it verifies nothing. Every fix in this review first probed actual rendered output (render → split lines → assert content), then pinned that.

Systemic

Swallowed errors turn assertion failures into misdiagnoses

integration helpers, examples, test setup events

_ = on setup/marshal/render errors makes downstream content assertions fail with misleading messages (or pass vacuously on empty output). Convention going forward: test helpers take *testing.T and fail at the source.

Docs drift is a security issue

The most dangerous findings came from docs/comments claiming behavior the code no longer has: the deleted nom concurrency model, daghtml's dedup lie, AGENTS.md's versioning model. Future sessions (human or AI) trust these and build on false ground.
