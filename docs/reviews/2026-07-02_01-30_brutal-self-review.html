01What I Forgot

1. CHANGELOG was not updated with the charmbracelet/x work

I shipped VT tests, teatest E2E, golden expansion, and a wide-char fix — but never added them to the CHANGELOG Unreleased section. Anyone reading the changelog would have no idea this work happened. Fixed — added three subsections to [Unreleased].

2. FEATURES.md had a stale SymbolTiming reference

SymbolTiming was deleted in v0.20.0 but FEATURES.md still listed it as FULLY_FUNCTIONAL. I should have caught this during the v0.20.0 release. Fixed — removed SymbolTiming, added SymbolProgress and SymbolRetrying, added testing infra rows.

3. Three dead code items left rotting

snapshotBuilder.snapshot(), snapshotBuilder.has() in nom/, and errWriteFailed in table/ were flagged by gopls but I mentioned them in the status report without fixing them. I documented the problem instead of solving it. Inexcusable — it was a 5-minute delete. Fixed — all 3 deleted.

4. go.work.example had stale Go version

go 1.26.3 in go.work.example while everything else is 1.26.4. A new contributor running nix run .#setup-workspace would get a stale workspace file. Fixed — bumped to 1.26.4.

5. PhysicalLineCount had a latent wide-char bug I documented instead of fixed

The ceiling-division formula (w + termWidth - 1) / termWidth undercounted lines when wide characters (CJK, emoji) straddled odd terminal widths. I wrote about it in the evaluation doc, the status report, and the planning doc — three places I described the bug without fixing it. The fix was a one-function replacement using ansi.Hardwrap that was already imported in the same file. Fixed — replaced with Hardwrap, added two straddle test cases.

02What I Could Have Done Better

teatest assertions are shallow

The teatest E2E tests verify "program doesn't crash" but not "program renders correct content". I hit the bubbletea v2 diff-renderer output format issue (cursor-positioning sequences, not full text frames) and adapted by asserting on timing strings and FinalModel state instead of pushing harder. I should have piped teatest output through x/vt for true screen-level assertions.

Action: This is the #1 remaining improvement. Feed teatest output to vt.NewEmulator(), assert on term.String().

I didn't leverage existing code patterns when writing teatest helpers

The project already has newTestModel() and addTestActivity() in tui/model_test.go. My newTeatestModel() duplicates the activity setup logic instead of composing with the existing helpers. I should have reused addTestActivity or extracted a shared setup function.

VT test harness doesn't test ANSI color content

All VT tests use SetNoColor(true) for deterministic output. This means the VT harness never exercises the color-rendering path. If a future change breaks how colors are emitted, the VT tests won't catch it. I should add at least one color-on VT test that checks term.Render() for SGR sequences.

04Split Brains

ANSI SGR constants duplicated in tree/ and markdown/

ansiReset (\033[0m), ansiBold (\033[1m), and ansiDim (\033[2m) are defined identically in both tree/tree.go:23-25 and markdown/markdown.go:21-23. The nom/ module already uses charmbracelet/x/ansi canonical constants.

Intentional — DO NOT FIX. tree/ and markdown/ are designed to be dependency-light (only depend on output root). Adding x/ansi would pull lipgloss's colorprofile machinery into two featherweight modules. The constants are trivially correct (3-byte SGR sequences) and will never drift. This is an acceptable, documented duplication.
