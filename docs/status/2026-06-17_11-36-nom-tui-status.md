## e) WHAT WE SHOULD IMPROVE!

### Architecture / type models

1. **Make `RenderNode` honest.** Either remove the unused `[]*TreeNode` parameter (requires ADR amendment / major version) or give it a real purpose (e.g., pass visible siblings for width-aware prefix calculation). Right now it is a ghost parameter.
2. **Introduce a proper `RenderContext` value object.** Width, color mode, selected node, and scroll offset are currently passed ad-hoc. A `RenderContext` struct would make impossible states unrepresentable (e.g., negative width) and simplify renderer signatures.
3. **Split `DisplayState` from tree structure.** `TreeNode` embeds `DisplayState` and mixes tree topology with presentation. Separate `NodeState` from `TreeNode` so the tree is pure structure and rendering computes presentation.
4. **Unify activity/step models.** `nom.ActivityDisplayState` and `tui.ProgressStep` represent nearly the same lifecycle. Consider a shared `Activity` domain type in `nom/` that `tui/` renders, instead of duplicating state in `ProgressModel.activities` and the subscriber.
5. **Make `ActivityStatus` exhaustive and ordered.** The status enum is implicit integers; a generated or strongly typed enum with an `Interest()` method would eliminate the switch in `activityInterest` and prevent accidental ordering bugs.
6. **Make `WorkflowState` a sum type or sealed interface.** Currently a `uint8`; a closed interface with `Idle`, `Running`, `Completed`, `Errored` implementations would make transitions type-safe.
7. **Decouple rendering from state mutation.** `InlineRenderer.Render()` mutates `prevLines` and writes to `writer`; `DependencyTree.Render()` acquires locks. Consider immutable snapshot-based rendering: copy the visible subset under lock, then render without holding state.
8. **Stop sharing `bytes.Buffer` between goroutines in tests.** The race in `TestInlineRenderer_Refresh_TriggersRender` was a test bug, but it points to a real pattern: production callers should use an `io.Writer` that is safe for concurrent writes (or serialize writes). Document this invariant.

### Code quality / libraries

9. **Replace hand-rolled ANSI parser with `charmbracelet/x/ansi`.** `StripANSI` and `ANSIPrefix` are already implemented in the charmbracelet ecosystem and likely handle edge cases (OSC sequences, hyperlinks) better than our regex-free parser. This removes `unicode/utf8` from the depguard allow-list.
10. **Use `lipgloss.Truncate` / `lipgloss.Width` where possible.** We already depend on lipgloss; reinventing width math in `terminal.go` is unnecessary for content that lipgloss styles.
11. **Use `charmbracelet/x/term` for terminal size.** We already use `golang.org/x/term`; evaluate whether `x/term` provides better cross-platform behavior or error handling.
12. **Add structured logging instead of `log.Printf` for TUI errors.** Per `how-to-golang`, use `slog` or `charm.land/log/v2` rather than `log.Printf` in `lifecycle.go`.
13. **Fix the integration TOML failure.** This is blocking `nix run .#test`. The fix likely involves changing how `serialization.MarshalTOMLFromTableData` represents the root document (e.g., a struct or map[string]any instead of `[]map[string]string`).
14. **Fix `tui/` data races.** These are real concurrency bugs, not just test artifacts. The pattern of mutating `ProgressModel` from both `ReportMessage` and the Bubble Tea event loop needs synchronization or proper Bubble Tea message dispatch.
15. **Run `go test -race` in CI for nom and tui.** Right now the race detector is not enforced; the pre-existing tui races prove it.

### Product / UX

16. **Collapse completed subtrees when height is limited.** Priority sorting is good; eliding entire completed branches is better for "see what's happening now."
17. **Add a `RenderOptions` value for `InlineRenderer`.** `maxHeight`, `hideCursor`, `noColor`, `appName`, and `startTime` are individually settable fields. A builder/options pattern would make configuration discoverable.
18. **Support mouse-click selection in the inline renderer?** The TUI supports selecting a node; the inline renderer does not. Decide if this is in scope.
19. **Progress bar / completion ratio in summary.** The NOM summary shows counts and elapsed time but no overall completion percentage.
20. **Keyboard shortcut overlay in inline renderer?** TUI has `?` help; inline mode has none.
