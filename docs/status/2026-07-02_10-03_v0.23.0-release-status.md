## E) WHAT WE SHOULD IMPROVE!

1. **Layered mode is not the default** — Tree mode is default for backward compat. Layered mode is arguably better for DAG-aware build systems. Consider ADR to switch default in v1.0.

2. **Category collapse only works in layered mode** — Tree mode would benefit from grouping children under phase nodes by category. Different algorithm needed.

3. **No live DAG visualization** — daghtml renders a static HTML snapshot. A live view (auto-refresh or websocket) of the running workflow DAG would be a killer feature.

4. **OSC 11 theme detection is env-var only** — COLORFGBG covers maybe 30% of terminals. True OSC 11 escape-sequence query requires async raw-mode terminal reading, which is non-trivial in Go without blocking.

5. **VT test helpers have unused methods** — `assertScreenNotContains` and `assertRowEmpty` are defined but never called. Either use them or remove them.

6. **No performance test for TUI** — teatest tests verify correctness but don't measure frame-rate or latency. A benchmark that drives the full TUI loop would catch rendering performance regressions.

7. **DAGSummary doesn't show in TUI** — The inline renderer has `SetShowDAGSummary(true)` but the TUI summary bar doesn't include it yet. The TUI has its own summary rendering path.

8. **examples/nom_dag is not in flake.nix apps** — Other examples (nom_progress, tui_progress) are in flake.nix. nom_dag should be added for consistency.

## G) THE #1 QUESTION

**Should layered mode become the default rendering mode in v1.0.0?**

Tree mode preserves nix-output-monitor compatibility and the indentation-based mental model users may rely on for tracking build phases. Layered mode makes parallelism explicit — arguably more useful for DAG-aware build systems like BuildFlow — but it's a visual breaking change for every existing user.

**I cannot figure out:** whether BuildFlow's users rely on the tree layout's parent/child connectors and indentation depth for mentally tracking which phase is which, or whether they'd welcome the layer-based layout as a strict improvement. This is a product decision that depends on real user feedback I don't have access to. If layered mode is strictly better, make it the default; if users have muscle memory for the tree layout, keep tree as default and leave layered as opt-in.
