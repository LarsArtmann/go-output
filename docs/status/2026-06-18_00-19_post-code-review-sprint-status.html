💡 E) WHAT WE SHOULD IMPROVE

  1. Single-session discipline: Never run two agent sessions on the same repo simultaneously. The collision risk is too high. If parallel work is needed, use branches.
  2. LSP cache invalidation: After renames, the LSP should be restarted. Add a post-rename step to the workflow.
  3. BDD coverage for concurrency: The race fixes (#20, #21) were verified with -race but not with BDD specs. Critical concurrency paths deserve Ginkgo specifications.
  4. Property-based testing for escape functions: The escape package now has 8 functions. Property tests (gopter) would verify idempotency and round-trip properties systematically.
  5. Integration test for DOT injection: The nodesep/ranksep validation (#31) should have an integration test that attempts injection and verifies rejection.
  6. Fuzz tests for D2/Mermaid/PlantUML renderers: Only D2 has fuzz coverage. The escaping gaps we found prove the other renderers need it too.
  7. API versioning strategy: The 7 deferred breaking changes need a concrete v1→v2 migration plan, not just NOTE markers.

❓ G) Top Question I Cannot Figure Out

Should the TUI reporter data race (#22) be fixed now or deferred to v1?

The BubbleTeaProgressReporter mutates pr.model.* fields (workflowState, steps, currentProgress) directly from the caller's goroutine while Bubble Tea's event loop goroutine concurrently reads/writes the same fields via Update(). This is a real data race detectable by -race.

The fix: Route ALL model mutations through tea.Program.Send — no direct field writes from the reporter. This means changing the reporter's entire API surface: ReportStep, ReportProgress, ReportError, ReportMessage, and transitionWorkflowState would all send messages instead of mutating directly.

Why I can't decide: This is an exported API change to the TUI module's reporter interface. ADR 006 says "all exported symbols frozen." But #22 is also the last remaining concurrency bug — a correctness issue, not a naming preference. Does the API freeze cover internal field access patterns of exported types, or just method signatures? I don't know where to draw the line.
