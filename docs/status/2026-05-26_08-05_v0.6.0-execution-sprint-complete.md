## E) WHAT WE SHOULD IMPROVE 🔧

### Architecture

1. **Generic Renderer[T] interface** — Currently 4 separate interfaces (Renderer, TableRenderer, TreeOutputRenderer, GraphRenderer). A generic `Renderer[T]` could unify them but risks over-abstraction.
2. **StreamingRenderer adoption** — Only HTML has streaming. JSONL, XML, CSV/TSV could all benefit. Interface requires importing output package which creates coupling.
3. **Typed columns in TableData** — Currently `[][]string` only. Richer type model could enable auto-formatting, alignment, type-aware serialization.

### Developer Experience

4. **Enum code generation** — 228 exported symbols include many hand-written enum methods (Parse, String, IsValid, AllowedValues). `stringer` or `go-enum` could auto-generate.
5. **Test helper deduplication** — `internal/gentest` is root-only, so d2/graph/serialization all inline their own helpers. Moving to `testhelpers/gentest` would help but exposes internal APIs.
6. **Root `go.mod` cleanup** — `go-faster/yaml` dep exists only for `internal/gentest/assert.go` test helpers. Could restructure to eliminate.

### Operations

7. **CI coverage threshold** — Done (80%), but could add per-module thresholds
8. **Release automation** — Manual tagging is error-prone. GoReleaser or GitHub workflow would help.
9. **CHANGELOG automation** — Manual entries risk getting stale.
