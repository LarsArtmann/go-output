### Release Process Automation

The current release flow is manual and error-prone (v0.36.0 and v0.37.0 both shipped with missing submodule tags, lightweight root tags, and no CHANGELOG promotion). These ideas address systemic release hygiene.

| Idea                                      | What                                                                                                                                                                                                                        | Why interesting                                                                                                                                                                      | Trigger to promote                                                                                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **GoReleaser-style multi-module tagging** | Automate root + 16 submodule tag creation from a single `nix run .#release` command. GoReleaser doesn't support Go workspaces natively, but a Nix-backed wrapper can iterate modules and create annotated tags in one step. | Every release since v0.34.0 has had tag parity issues (missing submodule tags, lightweight vs annotated, tag-message inconsistency). Automating eliminates the class of human error. | After `docs/RELEASE_CHECKLIST.md` and `scripts/tag-release.sh` are shipped (TODO_LIST #4, #6), evaluate whether the script should become a Nix app. |
| **Semver automation**                     | Script that bumps version across CHANGELOG, go.mod, and tags based on conventional commit messages.                                                                                                                         | Version bumps are currently manual and error-prone — v0.37.0 was tagged without promoting CHANGELOG `[Unreleased]` to `[0.37.0]`.                                                    | A second release occurs with the same CHANGELOG-promotion mistake, or a contributor requests a release process they can follow.                     |
| **CHANGELOG validation in CI**            | CI step that verifies the `[Unreleased]` section matches the commits since the last tag, and that tagged versions have a matching CHANGELOG entry with the correct date.                                                    | Catches the "tag exists but CHANGELOG not promoted" pattern that happened on both v0.36.0 and v0.37.0.                                                                               | After the release-checklist and tag-release script are in place.                                                                                    |

### Architecture

#### ~~Renderer Interface: `Render() (string, error)` — Code Smell~~

> **Resolved in v0.30.0.** The CQRS `WriteXxx(w io.Writer, model, opts...) error` (streaming, primary) and `RenderXxx(model, opts...) (string, error)` (convenience wrapper) pattern was implemented across all 16 formats. Registry dispatch now streams via CQRS functions. The original `Renderer` interface (`Render() (string, error)`) remains for backward compatibility but is no longer the primary API. See ADR 012.

## Explicit Non-Goals

| Non-goal                                | Why                                                                                                                                                                                |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Independently versioned sub-modules** | Pattern B (ADR 009) deliberately uses `v0.0.0` + `replace` for sibling deps. Only `testhelpers/` is independently consumable. This is not a limitation to fix — it's the design.   |
| **Non-Go language bindings**            | go-output is a Go library. The rendering patterns (Format/Shape enums, CQRS builders, registry dispatch) are Go-idiomatic. A port to another language would be a separate project. |
| **GUI or native app output**            | The library targets CLI applications (terminal tables, ASCII trees, diagram source code). A TUI exists for progress visualization but is not a general-purpose GUI framework.      |
| **Network protocol integration**        | All renderers write to `io.Writer`. Adding HTTP/gRPC/Kafka sinks would be a consumer's responsibility, not a library feature.                                                      |
