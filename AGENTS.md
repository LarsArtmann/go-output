# go-output

A reusable Go library for CLI output formatting (16 formats across table/tree/graph shapes) plus NOM-style real-time progress visualization. Multi-module Go workspace using committed `replace` directives with real released version pins (Pattern B, revised 2026-08-07); root is intentionally dependency-light and the primary independently `go get`-able module.

## Versioning Model — Pattern B (Committed Replace + Released Pins)

**Sub-modules are build-boundary optimizations, NOT independently designed packages.** Inter-module sibling deps pin REAL released versions (e.g. `v0.37.0`) AND carry `replace => ../path` directives. History: until 2026-06-23 siblings used the `v0.0.0-00010101000000-000000000000` sentinel; commit `d16650b` (2026-08-07) bumped all sibling requires to the released `v0.37.0` so `go mod tidy` and CI resolve published artifacts instead of replace-only pseudo-versions.

- `go get github.com/larsartmann/go-output` works (root has only external deps + `testhelpers`).
- Sub-module `go get` resolves to the published release (pins are real); local development still goes through the committed `replace` directives — the local tree always wins over the pin.
- **Every release must re-bump all sibling pins** to the new version across all `go.mod` files (ADR 009 amendment + RELEASE_CHECKLIST step pending, TODO item 20).
- `testhelpers/` keeps real published versions and is genuinely independently useful; `daghtml/` and `escape/` are zero/low-dep and independently publishable.
- Sub-modules are consumed via clone + `go.work` (run `nix run .#setup-workspace`).
- Never delete the `replace` directives — they are what makes local development hermetic.

## The Core Invariant

**Root (`package output`) has ZERO imports of any sub-module.** This is the load-bearing architectural rule. Everything else follows from it.

- `go get github.com/larsartmann/go-output` pulls NO lipgloss, NO bubbletea, NO yaml/toml, NO d2/graph/table/nom/tui deps.
- Sub-modules self-register into root's registries via their own `init()` (see Patterns). Root never imports them back.
- **Never** add an `import ".../table"`, `".../d2"`, `".../nom"`, etc. to a file in the root package. It breaks the entire dependency-isolation guarantee.
- `enum` and `envdetect` packages were merged INTO root in v0.18.0 — their functions (`ParseEnum`, `ContainsEnum`, `IsCI`, `IsNoColor`, etc.) are now in `package output`. The old `enum/` and `envdetect/` sub-modules no longer exist.

**Nix is the source of truth.** `go build ./...` from root only builds root — always use the flake apps, which iterate every module:

```bash

nix run .#test             # Test all 19 modules
nix run .#test-race        # Race-test nom + tui (concurrency-sensitive)
```

Go checks are NOT in `nix flake check` (sandbox blocks `go mod download`); CI handles them. `.pre-commit-config.yaml` exists for non-Nix users.

## Patterns

These are non-obvious from reading code alone — the "how does this even work" knowledge.

- **Pattern B versioning (released pins + committed replace)**: All sibling deps pin the latest released version (e.g. `v0.37.0`) with `replace => ../path`. The `replace` makes local dev hermetic (local tree always wins over the pin); the real pins make `go mod tidy`/CI resolve published artifacts. On every release, bump all sibling pins across the go.mod files (ADR 009 amendment pending, TODO item 20). Until 2026-08-07 siblings used the `v0.0.0` sentinel; `d16650b` replaced that model — do not revert to sentinels.
- **Release tag convention — 17 tags per release**: Every release creates 1 root tag (`vX.Y.Z`) + 16 submodule tags (`<module>/vX.Y.Z`), ALL annotated (`git cat-file -t` returns `tag`, never `commit`), ALL on the same commit. Excluded from tagging: `examples/` and `integration/` (test-only). Use `scripts/tag-release.sh vX.Y.Z` as the primary path — it runs the full sequence and verifies parity. The `release.yml` workflow auto-creates missing submodule tags as a safety net. The `pre-tag-check.sh` script verifies tag-family parity (latest release has all 17 annotated tags). See `docs/RELEASE_CHECKLIST.md`. This convention exists because v0.36.0 AND v0.37.0 both shipped without submodule tags — the auto-tagging in release.yml is the systemic fix.
- **Registry dispatch via `init()`**: Root's `RenderTable()` / `RenderUnknown()` dispatch to registered marshalers, yet root imports no sub-module. Each sub-module calls `RegisterFormatShapes(...)` / registers its marshaler in its own `init()`. The generic `formatRegistry[T]` backs shape capabilities, table, and unknown registries. Importing a sub-module is what activates it.
- **Enum utilities are in root**: `ParseEnum[T]`, `ContainsEnum[T]`, `EnumAllowedValues[T]`, `EnumAllowedStrings[T]` live in `package output` (file: `enum.go`). Sub-modules call them via `output.ParseEnum[T](...)`. The `StringEnum` interface and `ParseError` type are also in root.
- **CI/NO_COLOR detection is in root**: `IsCI()` and `IsNoColor()` live in `package output` (file: `envdetect.go`). `CIEnvVars` is the exported list of CI env var names. Sub-modules call `output.IsCI()` / `output.IsNoColor()`.
- **Shape capability matrix**: Each format declares which data shapes (table/tree/graph) it supports via `RegisterFormatShapes()` in `init()`. Query with `f.Supports(shape)` or `FormatsForShape(shape)`. See `docs/FORMAT_ARCHITECTURE.md`.
- **ColorMode wiring — three mechanisms, use the right one**: `table.New(table.WithColorMode(...))` (functional option), `ASCIITreeRenderer.SetColorMode(...)` / `MarkdownTable.SetColorMode(...)` (setter), `RenderTable(data, fmt, RenderOptions{ColorMode: ...})` (dispatch field). `ColorModeAuto` detects terminal via `x/term`, respects `NO_COLOR`/`CI`/`FORCE_COLOR`.
- **Semantic color delegation**: `tui/colors.go` delegates its 4 activity-state colors (`success`/`warning`/`err`/`dim`) to `nom.Colors` (`Completed`/`Running`/`Failed`/`Pending`) — nom is the single source of truth for the palette. TUI-only colors (title, selection, help) stay local. Do not re-duplicate ANSI codes between nom and tui.
- **Composition via `GraphBuilder`**: DOT/Mermaid/PlantUML renderers embed root's `GraphBuilder` for shared node/edge state via `AddNode`/`AddEdge`. `AddTreeNodes` accepts the `NodeEdgeAppender` interface (not raw slice pointers). `TableStore` exposes `Data()` so sub-modules share the table data field.
- **Branded IDs**: Phantom types (`D2NodeID`, `TreeNodeID`, ...) via `go-branded-id` prevent mixing ID types at compile time. `d2/` re-exports `D2NodeID`/`D2NodeLabel` from root so users need only one import.
- **Render naming convention**: `Render() (string, error)` is the project-wide canonical contract for `output.Renderer` and its implementations — use `MustRender(r)` in tests. `nom.InlineRenderer.Draw()` is reserved for terminal redraws (void, writes to `io.Writer`). `nom.DependencyTree.RenderWithSnapshots(snapshots, maxHeight, maxWidth)` returns a formatted string (errors encoded into the string). The old `RenderString`/`RenderWithWidth`/`VisibleNodes` convenience wrappers were deleted because they silently passed nil snapshots — always use the explicit `WithSnapshots` variants.
- **Dedup workflow (do this BEFORE refactoring clones)**: Load the `deduplicate-code` skill → run `art-dupl -t 4` for the production gate and `art-dupl --sort total-tokens -t 1 --type-aware` for strict audits → for every clone group, apply the ADR 005 checklist in order: (1) generated/single-line/interface-compliance? → accept; (2) structural or semantic? if idiomatic Go test pattern (`strings.Contains`, `t.Errorf`, table-driven) → accept; (3) would abstraction help readability? if no → accept; (4) drift likely? if no → accept; (5) only fix **production** clones where identical logic is duplicated. Keep `examples/` visible in strict scans but accept its self-contained documentation patterns; do not exclude or refactor them solely for metrics. The codebase is at **zero clones at t=4**, **2 accepted groups at t=3** (strings.Builder + RLock minimum idioms), **16 at t=2**, and **20 accepted groups at strict type-aware t=1** as of 2026-07-26.
- **Current dedup state**: t=4 has **0** groups (production gate clean); t=3 has **2** accepted minimum idioms; t=2 has **16**; t=1 has **20** (all accepted). The 2 at t=3 are: (a) the `ns.mu.RLock() / defer ns.mu.RUnlock() / time.Now()` pattern (nom.SnapshotActivities + nom.EstimatedTotalRemaining — minimum idiom for thread-safe time reads); (b) the `var b strings.Builder` opener (markup.MarshalXMLFromTable + plantuml.PlantUMLDiagram.Render — minimum idiom for string concatenation). The 16 at t=2 add: `t.Parallel()`/`t.Helper()` test boilerplate (39 sites), examples `if err != nil` blocks (5 groups, Category D — self-contained documentation), the functional-option `Option func(*Config)` pattern (markdown+tree — Go requires distinct closure types per module), canonical Marshal/Unmarshal wrappers (toml/yaml — abstraction hurts readability), `markup.writeBytes` vs `output.WriteRenderedRaw` (different error semantics: fragment-context vs format-output), markup builder-execute-return (canonical template idiom), and `pr.ensureStarted()` (method reuse, not duplication). The v0.32 sweep added `output.ColorConfig`, `output.DefaultColorConfig()`, `output.WriteRenderedRawFrom`, `output.WriteRenderedFrom`, `serialization.stringFromBytes`, `serialization.renderUnknown`, `escape.ANSIReturn`/`Bold`/`Dim`, `markup.writeBytes`, `nom.withLockedActivity`, and `output.NewTableWithRow`. The July 26 t=2 pass extracted `serialization.renderUnknown` (mirrors `renderTable`) and rewired `markdown/registry.go` to use `output.WriteRendered` (exact error-match, eliminating a reimplemented root helper).
- **nom phase detection is `ActivityKind`-based (not ID prefix)**: `ActivityKind` (`ActivityKindTask` / `ActivityKindPhase`) is set at construction via `NewPhase(id, name)`. `ActivitySnapshot.IsPhase()` reads it directly. The old `"phase:"` ID-prefix convention and `isPhaseID` were deleted in v0.17.0 — never re-introduce string-based kind detection. Phase nodes render with `SymbolPhase`/`ColorPhase` instead of status-derived styling.
- **nom snapshot model (not shared pointers)**: `ActivityNode` holds only an `ActivityID`, DAG topology (`Deps []ActivityID`), and display layout (`Parent`/`Children`) — it does NOT embed `*Activity`. All mutable activity fields are consumed via `ActivitySnapshot`, an immutable value copy taken under the subscriber's read lock (`SnapshotActivities()`). This eliminates the data race that the old shared-`*Activity`-pointer model caused. Never re-introduce a shared mutable pointer between the subscriber and the tree; always go through snapshots.
- **nom DAG topology (v0.22.0)**: `ActivityNode.Deps []ActivityID` stores ALL real dependency edges — the true DAG. `Parent`/`Children` are DISPLAY layout only, computed at `Build()` time. `Build()` runs a fixpoint depth computation (longest path from root) then picks each node's deepest dep as `DisplayParent` (matching nom's "lowermost dependency" rule — shared deps sink toward leaves). `ExtraDeps()` returns deps minus the display parent's ID. The old `SecondaryParents` field and the `←` inline annotation are deleted. Option A (default): no annotation, matching nom. Option B (`WithShowExtraDeps()`): dim `↳ Compile, Lint` sub-line beneath the label. `subscriberView.Edges()` iterates `Deps` (not `Children`) so diagram export captures ALL edges. `AddActivity` with empty deps preserves existing deps (ActivityStarted calls AddActivity with nil deps after ActivityRegistered).
- **nom activity counts are incrementally cached (O(1), not O(n))**: `NOMSubscriber.counts` is an `ActivityCounts` value maintained via `applyCountsDelta(&counts, oldStatus, newStatus)` on every state transition in the event handlers, and zeroed in `Reset()`. `GetActivityCounts()` reads this cache directly — it must NEVER scan `ns.activities`. This replaces the old per-frame O(n) scan of all activities. If you add a new mutation path to `ns.activities` (create, transition, delete), you MUST update `ns.counts` in the same handler under the same write lock. The invariant is verified by `TestActivityCountsCache_LifecycleConsistency` (brute-force recount vs cache after every event).
- **nom elapsed time is derived at snapshot time (no per-tick write)**: `Activity.CurrentElapsed` field was deleted entirely — it was only ever read into `ActivitySnapshot`. `SnapshotActivities()` now calls `activity.elapsedAt(now)` which computes `now-StartTime` for running activities and `EndTime-StartTime` for terminal states. The old `UpdateRunningActivityElapsed()` method (O(n) write scan every 100ms tick) is gone. `ActivitySnapshot.CurrentElapsed` remains — renderers read it unchanged. Never re-introduce a per-tick mutation to stamp elapsed; the snapshot is always current by derivation.
- **InlineRenderer locking model (two mutexes, on purpose)**: `tickMu sync.RWMutex` guards config + lifecycle fields; `renderMu sync.Mutex` serializes terminal writes + `prevLines` + `lastFrame`. They MUST stay separate — merging them reintroduces the `Stop()` deadlock (the refresh loop's `Draw()` takes `tickMu.RLock`, so holding the write lock across `<-tickerDone` would deadlock). All config reads go through one `snapshotConfig()` call returning an immutable `rendererConfig` (one `RLock`, not scattered field reads). Setters (`SetStartTime`/`SetAppName`/`SetNoColor`/`SetHideCursor`/`SetMaxHeight`/`SetPlainText`) take `tickMu.Lock` and are safe to call during the render loop. `lastFrame` is guarded exclusively by `renderMu` — the "force redraw on mode change" signal flows through the config snapshot (`lastFramePlain` tracks the mode alongside the frame string), never crossing the mutex boundary.
- **InlineRenderer CI/plain-text degradation**: `detectPlainText()` (called once at construction) returns true under `output.IsCI()`. In plain mode `Draw()` appends each frame on its own line, skipping cursor-up/clear-line/sync-region escape codes that corrupt captured CI logs. Colors are separately suppressed via `detectNoColor()` (same env signals). Both delegate to root's `IsCI()`/`IsNoColor()` — don't re-inline.
- **InlineRenderer height-pressure collapse**: when the tree exceeds `maxHeight`, `elideCompletedUnderPressure` drops completed children and the renderer emits a faint `⋯ N completed` marker so the collapsed work is visible (the summary bar still carries aggregate counts). `SetMaxHeight` updates the cap at runtime, race-free.
- **InlineRenderer frame diffing (skip identical redraws)**: `Draw()` compares the new frame against `lastFrame` and emits zero bytes when identical (mirrors bubbletea v2's `cursedRenderer.viewEquals()` early-exit). A `listenForResize` goroutine handles SIGWINCH — on terminal resize it invalidates `lastFrame` to force a full redraw. `refreshLoop` carries a deferred `recover` that restores the cursor on crash.
- **InlineRenderer writer-aware TTY detection**: `detectNoColor()` / `detectPlainText()` probe the writer's own FD via `x/term.IsTerminal`, not the hardcoded `os.Stdout`. `writerIsTTY` is authoritative — `snapshotConfig()` computes `effectivePlainText = plainText || !writerIsTTY`. A non-TTY writer always degrades to plain text; the only valid direction is TTY→plain, never pipe→inline. Sync-output codes (`\033[?2026h`/`\033[?2026l`) are emitted only when `writerIsTTY` is confirmed.
- **Sealed Event sum type (v0.17.0)**: `nom.Event` carries an unexported `isEvent()` marker — only the concrete structs in `nom/event.go` can implement it (currently 9: WorkflowStarted/Completed/Failed, ActivityStarted/Registered/Completed/Failed/Progress/Retrying). Handlers route via exhaustive Go type switch, not string dispatch. Adding a new event type means the compiler errors on every non-exhaustive switch — this is by design. Never re-introduce `GetEventType()` string dispatch or accessor interfaces.
- **TUI scroll rendering (entry-level windowing)**: NOM mode scrolls at the `VisibleEntry` level — `renderDependencyTree()` collects all entries, slices `[offset:offset+height]`, then renders only the visible window. This replaced the old O(n) render-entire-tree-then-string-clip. Universal mode still uses `applyScrollViewport()` (string-level clipping) because its step list has no entry abstraction. `scrollToBottomSentinel = 1<<30` is clamped to `maxOffset` on render. `SetDisplayMode()` resets `scrollOffset=0` to prevent stale cross-mode positions. Mouse click mapping uses `m.visibleEntries[treeLine]` without adding `scrollOffset` (entries already contain only the visible window).
- **Progress/Retry events (v0.21.0)**: `ActivityProgress{ID, Name, Message}` sets a live sub-step message rendered as a dim `→ message` sub-line; `ActivityRetrying{ID, Name, Attempt, Reason}` transitions a failed activity back to running, bumps `RetryCount`, and renders `⟳N (reason)`. Both are sealed event types routed through `OnEvent`'s type switch. `SetRunning()`/`SetCompleted()`/`SetFailed()` all clear `Progress` (a retry starts fresh), while `RetryCount`/`RetryReason` persist across transitions (a completed-then-retried step keeps its `⟳N`). Direct accessors `SetActivityProgress(id, msg)` and `SetEstimatedTime(id, d)` exist for callers bypassing the event path.
- **EstimatedTotalRemaining is subscriber-owned (v0.21.0)**: `NOMSubscriber.EstimatedTotalRemaining()` sums per-activity remaining estimates (full `EstimatedTime` for pending, `max(0, EstimatedTime - elapsed)` for running; terminal activities contribute nothing). It is the single source of truth for the `~Xm left` summary segment. The TUI consumes it directly via `renderNOMSummaryBar`; the inline renderer has its own `SetEstimatedRemainingFunc` callback override (for callers like BuildFlow with an external `TimeEstimator`) but can delegate to this method. Do not re-implement the sum in a second place.
- **TUI NOM rendering delegates to nom**: the TUI's `renderDependencyTree()` calls `tree.RenderVisibleEntry(entry, snapshots, width)`, which routes through `formatActivityLabel`. So any new activity-snapshot field rendered by `formatActivityLabel` (Progress, RetryCount/Reason, Download bar, Host) is automatically visible in BOTH the inline renderer and the TUI — no separate TUI view-layer update is needed. The TUI only needs its own code for TUI-exclusive chrome (summary bar coloring, scroll, help overlay).
- **daghtml embedded DAG visualization**: `daghtml/` is a zero-dependency module (like `escape/` and `testhelpers/`) that renders interactive SVG DAGs in HTML pages. It uses `html/template` (NOT `templ` — templ v0.3.x doesn't evaluate expressions inside `<script>`/`<style>` text nodes) with `template.CSS`/`template.JS`/`template.JS` typed injection for XSS safety. The `DAG{Nodes, Edges}` data model is deliberately minimal and JSON-serialized; each consumer project writes its own adapter (`buildDAGHTML(report) → daghtml.DAG`). JS uses class selectors (`.graph-zoom-in`, `.dag-container`) not IDs, to support multiple graphs per page. Consumers inject the JS via `daghtml.Script()` and the data via `dagToJSON()`. External consumers (go-workflow-auditlog, samber-do-auditlog) use `v0.0.0-…` + `replace` for local dev; daghtml is independently publishable since it's zero-dep.
- **VT emulator test harness (nom/)**: `nom/vttest_test.go` provides `vtHarness` — wraps `charmbracelet/x/vt.Emulator` as an `io.Writer` with screen-content assertion helpers. Tests prefixed `TestVT_*` in `nom/vt_renderer_test.go` feed InlineRenderer output to a real VT emulator and assert on the screen buffer (what a terminal would actually display), not on raw escape sequences. This replaces the old fragile `strings.Contains(buf, "\x1b[A")` assertions. The harness tracks `cursorHidden` and `syncWasActive` via VT callbacks. When adding new escape-sequence behavior to the InlineRenderer, add a `TestVT_*` test to verify the screen-level output.
- **teatest/v2 E2E tests (tui/)**: `tui/teatest_helpers_test.go` provides `newTeatestModel()` — wraps `ProgressModel` in `charmbracelet/x/exp/teatest/v2` (NOT v1 — incompatible with `charm.land/bubbletea/v2`). Tests prefixed `TestTeatest_*` drive the REAL Bubble Tea program loop (Init, Update, View, Cmd dispatch). The bubbletea v2 diff renderer writes cursor-positioning escape sequences, not full text frames — so tests assert on ANSI-stripped output via `waitForVisible()` (which uses `ansi.Strip`) or on `FinalModel` state. **`waitForVisible(tm, "Build Module")` verifies initial content rendered; `waitForTick(tm)` verifies the program is still alive after keypresses** (the diff renderer only emits changed regions post-keypress, not the full screen — so content-based waits time out). Key E2E coverage: program startup, scroll key handling, help toggle, quit propagation, ctrl+c, WindowSizeMsg dispatch, goroutine-leak check (`TestTeatest_NoGoroutineLeak`). **Never use `teatest.WaitFor` directly** — it internally calls `io.ReadAll(io.TeeReader(...))` which blocks indefinitely when the tick loop writes continuously (the output buffer never empties for EOF). Always use `pollTeatestOutput()` (in `teatest_helpers_test.go`) which does bounded single-`Read` polling instead. `newTeatestModel` cleanup calls `tm.Quit()` + `tm.WaitFinished(t, teatest.WithFinalTimeout(3*time.Second))` — the `WaitFinished` is critical: without it the program goroutine leaks and the test binary hangs under `-race` at the timeout.
- **Golden-file testing in table/, tree/, graph/, d2/, serialization/, plantuml/**: All six renderer modules now have `golden_test.go` using `charmbracelet/x/exp/golden`. All golden tests use `ColorModeNever` for deterministic output. Generate/update golden files with `go test -run TestGolden_ -update`. Golden files live in `testdata/*.golden`.
- **teatest VT screen assertions (tui/)**: `tui/teatest_vt_test.go` pipes teatest's raw diff output through `charmbracelet/x/vt` and asserts on the reconstructed screen buffer. This is deeper than ANSI-stripped text — it proves the diff renderer's cursor sequences produce correct visible content. Pattern: `vtScreenFromBytes(t, raw, width, height)` → screen string → `strings.Contains`.
- **Color-on VT testing (nom/)**: `TestVT_ColorOn_EmitsSGR` forces `lipgloss.Writer.Profile = colorprofile.ANSI` (with `t.Cleanup` restore) to verify SGR codes are emitted and processed into cell foreground colors. NOT parallel (mutates global profile). All other VT tests use `SetNoColor(true)` for deterministic output.
- **Fuzz testing**: `nom/format_fuzz_test.go` (FormatDuration) and `nom/format_activity_label_fuzz_test.go` (formatActivityLabel) are the two fuzz targets. Run with `go test -fuzz=FuzzFormatActivityLabel -fuzztime=10s`. Seed corpus covers unicode, emoji, newlines, and extreme lengths.
- **Theme system (v0.23.0)**: `nom.Theme` struct holds `SemanticColors`, symbol overrides (`Symbols map[ActivityStatus]Symbol`), and `CategoryColors map[ActivityCategory]color.Color`. Five presets: `ThemeDefault`, `ThemeDracula`, `ThemeNord`, `ThemeMonochrome`, `ThemeHighContrast`. Set via `WithTheme(theme)` subscriber option. The theme is stored on both the subscriber and the dependency tree. `SnapshotActivities()` resolves color/symbol via the subscriber's theme at snapshot time, so `ActivitySnapshot` carries themed values and renderers don't need the theme passed explicitly. The TUI reads `ns.Theme()` and passes it to state-aware styling. `Theme.ColorFor(kind, status)` and `Theme.SymbolFor(status, default)` are the resolution methods.
- **Layered display mode (v0.23.0)**: `RenderMode` (`RenderModeTree` / `RenderModeLayered`) selects how the dependency tree is displayed. Set via `WithRenderMode(mode)` or `DependencyTree.SetRenderMode(mode)`. In layered mode, `collectLayeredEntries` groups nodes by DAG `Depth` and emits one `VisibleEntry` per line: layer headers (`"Layer N"`), per-node rows (`LayerNodes`), and separator lines. Nodes are priority-sorted (running > pending > failed > completed). Structural placeholder nodes (created only to satisfy a dependency edge, no snapshot label) are skipped. Height-pressure collapse summarizes fully-terminal layers as `"✔ Layer N: N done"`. `RenderVisibleEntry` dispatches to `renderLayeredLine` for layered entries. `VisibleEntry.ContainsNode(id)` checks both `Node` and `LayerNodes`. TUI selection and mouse click handlers support `LayerNodes` rows.
- **Activity categories (v0.23.0)**: `ActivityCategory` (a `string` type) tags activities with a semantic group ("build", "test", "deploy"). Stored on `Activity.Category` and `ActivitySnapshot.Category`. Set via `ActivityRegistered{Category: ...}`, `ActivityStarted{Category: ...}`, or `SetActivityCategory(id, cat)`. Rendered as a dim `[tag]` prefix when `WithShowCategory()` is enabled. The theme's `CategoryColors` map provides optional color tints per category. `labelOptions.ShowCategory` controls rendering in both tree and layered modes.
- **Status registry (v0.23.0)**: `StatusDef` entries are registered in a global registry via `RegisterStatus()`. Core statuses (pending/running/completed/failed) are pre-registered at init. `LookupStatus(status)` returns the `StatusDef`. `ActivityStatus.String()`, `GetSymbol()`, `GetColor()`, `Interest()`, `IsValid()`, `ParseActivityStatus()`, and `AllowedValues()` all delegate to the registry. `AllActivityStatuses()` returns all registered entries in ascending ID order. Custom statuses are supported — the flaky parallel test `TestStatusRegistry_AllActivityStatuses_IncludesCustom` was fixed to not assert exact count deltas (the global registry grows when parallel tests register custom statuses).
- **Critical-path ETA (v0.23.0)**: `DependencyTree.EstimatedCriticalPathRemaining(snapshots)` computes the longest remaining-time path through the DAG using fixpoint iteration. Running nodes contribute `max(0, estimated - elapsed)`; pending nodes contribute full estimate; terminal nodes contribute 0. `InlineRenderer.SetShowCriticalPathETA(true)` renders a `"~Xm critical"` segment in the summary bar. The existing `EstimatedTotalRemaining()` (subscriber-owned sum) remains the source for `"~Xm left"`.
- **Critical-path priority sort (v0.23.0)**: `sortKey` now carries an `onCriticalPath bool` field. In `sortKey.less`, critical-path nodes sort before non-critical at the same interest level. `childPriority` accepts a `criticalPath map[ActivityID]bool` parameter (nil = no boost). When `showCriticalPath` is enabled, the critical path map is passed through from `collectVisibleNodes` → `walkSubtree` → `childPriority`.
- **Parallelism meter (v0.23.0)**: `ParallelismStats{Running, Possible}` reports how many activities are running and how many more could start immediately (all deps satisfied). `NOMSubscriber.ParallelismStats()` acquires `ns.mu.RLock` then `tree.mu.RLock` (matching `Edges()` ordering). Rendered as `"parallel: N/M possible"` via `WithShowParallelism()`.
- **CQRS builders (v0.30.0)**: Three write-side builders in root: `GraphBuilder` (has `AddNode`/`AddEdge`/`Build()→Graph`), `TableBuilder` (has `SetHeaders`/`AddRow`/`SetFooter`/`Build()→*Table`), `TreeBuilder` (has `SetRoot`/`AddChild`/`Build()→*TreeNode`). All use fluent API (methods return the builder pointer for chaining). `GraphBuilder.Build()` returns an immutable `Graph` (unexported fields, only `Nodes()`/`Edges()` accessors). `TableBuilder.Build()` copies slices so subsequent builder mutations don't affect previously built tables. Old renderer structs (DOTRenderer, MermaidRenderer, etc.) still exist as implementation detail behind the CQRS pure functions.
- **CQRS pure-function renderers (v0.30.0)**: Every renderer module exports `WriteXxx(w io.Writer, model, opts...) error` (primary, streaming) and `RenderXxx(model, opts...) (string, error)` (convenience). Naming convention: `Write` is primary, `Render` wraps `Write` with a `strings.Builder`. Modules: `graph.RenderDOT/WriteDOT`, `graph.RenderMermaid/WriteMermaid`, `d2.Render/Write`, `d2.RenderGraph/WriteGraph`, `plantuml.Render/Write`, `tree.RenderASCII/WriteASCII`, `markdown.Render/Write`, `delimited.RenderCSV/WriteCSV`, `delimited.RenderTSV/WriteTSV`, `serialization.RenderJSON/WriteJSON` (also YAML/TOML/JSONL), `markup.RenderXML/WriteXML` (also HTML/AsciiDoc). Each module has its own `Option` type and `With*` functional options.
- **Cross-shape projections (v0.30.0)**: Pure functions in root that convert between data shapes: `TableToGraph(t, opts...)→Graph` (one node per row, edges between consecutive rows; accepts `WithGraphNodeLabelFunc(fn)` option), `GraphToTree(g)→*TreeNode` (follows edges from root, cycle-guarded; only first root's subtree for disconnected graphs), `GraphToTable(g)→*Table` (one row per node, columns ID+Label). These are projections — the input is never modified.
- **CQRS streaming via standard encoders (v0.30.0)**: All `WriteXxx` functions in serialization/delimited/markup stream directly via standard encoders (`json.NewEncoder(w).Encode()`, `yaml.NewEncoder(w).Encode()`, `toml.NewEncoder(w).Encode()`, `NewCSVWriter(w)` row-by-row, `NewXMLWriter(w)` element-by-element). No intermediate `[]byte`/`string` allocation. The encoders add trailing `\n` (canonical Go behavior); the old `MarshalXxx→string→Fprint` path did not. CQRS golden files (`testdata/TestGolden_CQRS_*.golden`) lock in the exact streaming output byte-for-byte. HTML and AsciiDoc still buffer (no streaming writer exists for those formats — they call `renderHTMLTable`/`MarshalAsciiDocFromTable` then write).
- **Registry dispatch rewired to CQRS (v0.30.0)**: `output.RenderTable(data, FormatJSON, opts)` now calls `serialization.WriteJSON(w, data)` — the same streaming code path as the CQRS API. This means registry dispatch and CQRS produce **byte-for-byte identical output** (proven by `TestCQRS_StreamVsRegistry_JSON/CSV` in integration/). The old `renderViaRenderer` (serialization) and `renderDelimitedTable` (delimited) helpers were removed as dead code. The old renderer structs (`JSONTableRenderer`, etc.) still exist for direct callers but are no longer the registry dispatch path. JSON/YAML/TOML registry output now has a trailing `\n` — this is a documented breaking change in v0.30.0.
- **graph.WriteDOT writes directly from Graph (v0.30.0)**: The CQRS `WriteDOT` function calls the shared `renderDOTString(nodes, edges, cfg)` function directly — no `DOTRenderer` intermediary is created, populated, or rendered. `DOTRenderer.Render()` delegates to the same `renderDOTString` function, ensuring zero formatting duplication between the CQRS and legacy paths. When DOTRenderer is deleted in v0.31.0, `renderDOTString` remains as the single DOT formatting implementation.
- **Shared write/marshal helpers in root (v0.31.0)**: Four root helpers remove the per-module 5-line copy/paste that every sub-module's renderTable/Write/Render used to carry. `output.WriteRendered(w, format, out)` writes with trailing `\n` (used by diagram `renderTable` marshalers + `table.Write`). `output.WriteRenderedRaw(w, format, out)` writes WITHOUT trailing `\n` (used by `markdown.Write`, `plantuml.Write`, `tree.WriteASCII` where the rendered payload already ends in `\n`). `output.RenderFromWrite(writeFn)` adapts a `Write(w) error` into a `Render() (string, error)` (used by every sub-module's `Render` wrapper). `output.MarshalViaRenderer(data, format, newRenderer)` is the shared body of every `MarshalXxxFromTable` whose implementation is "construct-renderer, SetData, Render, cast []byte" (used by `markup.MarshalAsciiDocFromTable` and `serialization.MarshalTOMLFromTable`). All four are in `write_rendered.go` / `marshal_helpers.go`.
- **Render-then-write helpers (v0.32)**: `output.WriteRenderedFrom(w, render, formatName, formatErrorPrefix)` and `output.WriteRenderedRawFrom(w, render, formatName, formatErrorPrefix)` collapse the canonical `out, err := renderer.Render(); if err != nil { return fmt.Errorf("%s: %w", err) }; return output.WriteRendered*` pattern into a single call. Pass the renderer's `Render` method as a method value (e.g. `m.Render`). Used by markdown.Write, plantuml.Write, tree.WriteASCII, table.Write, table.renderStyledTable, tree.renderTreeTable.
- **Shared color-mode config (v0.32)**: `output.ColorConfig{ColorMode ColorMode}` is embedded by every sub-module's CQRS Config that needs color control (markdown, tree). `output.DefaultColorConfig()` returns the canonical `ColorModeAuto` initial value. Replaces the per-module `colorMode output.ColorMode` field that was duplicated across modules.
- **Serialization marshal helper (v0.32)**: `serialization.stringFromBytes(format, subject, data, err)` wraps the standard "marshal bytes to string with format/subject error context" idiom shared by all TOML/YAML/JSON tree+graph renderers.
- **Serialization unknown-render helper (v0.32)**: `serialization.renderUnknown(w, data, formatName, marshalFunc)` mirrors the existing `renderTable` helper but for the "unknown data shape" path — it marshals then writes via `output.WriteRendered`. Shared body of `renderJSONUnknown`/`renderTOMLUnknown`/`renderYAMLUnknown` (JSON passes a closure to preserve `json.Deterministic` + indent options).
- **Markup write helper (v0.32)**: `markup.writeBytes(w, errCtx, content)` wraps `io.WriteString` with a contextual error message. Replaces the `_, err := x.Writer.Write(...); if err != nil { return fmt.Errorf("%s: %w", err) }` pattern repeated 5× in markup/xml.go.
- **Nom locked-activity helper (v0.32)**: `nom.withLockedActivity(id, name, kind, apply)` acquires `ns.mu`, calls `getOrCreateActivity`, and invokes `apply` while still holding the lock. The no-state-change counterpart of the existing `transitionTask` helper. Replaces the `ns.mu.Lock(); defer ns.mu.Unlock(); activity := ns.getOrCreateActivity(...)` pattern in handleActivityStarted, handleActivityRegistered, handleActivityProgress.
- **Test scaffolding helper (v0.32)**: `output.NewTableWithRow(headers []string, row ...string) *Table` collapses the `output.NewTable(headers) + table.AddRow(row)` test fixture pattern into one call. Used in 14 test sites across delimited, integration, markdown, markup, serialization.
- **Shared ANSI constants (v0.32)**: `escape.ANSIReturn`/`ANSIBold`/`ANSIDim` (`\033[0m`, `\033[1m`, `\033[2m`) replace the per-module `ansiReset`/`ansiBold`/`ansiDim` constants previously duplicated in markdown and tree. Both modules now depend on `escape`.
- **GraphBuilder is fluent (v0.31.0)**: `NewGraphBuilder()` returns `*GraphBuilder` (not value) and `AddNode`/`AddEdge` return `*GraphBuilder` so callers can chain `output.NewGraphBuilder().AddNode(...).AddEdge(...).Build()`. The `NodeEdgeAppender` interface was widened to match. Embedded uses (`JSONGraphRenderer`, `TOMLGraphRenderer`, `YAMLGraphRenderer`, `DOTRenderer`, `MermaidRenderer`, `PlantUMLDiagram`) construct with `GraphBuilder: *output.NewGraphBuilder()`. This is a Frozen-API change documented in ADR 014.
- **encoding/json/v2 migration**: Production code uses `encoding/json/v2` (semantic layer) and `encoding/json/jsontext` (syntactic layer). Key differences from v1 that shaped the migration: (1) `json.Deterministic(true)` is passed to every `Marshal`/`MarshalEncode` call to preserve v1's alphabetical map key ordering — without it, `map[string]string` keys are non-deterministic and CQRS-vs-registry output diverges; (2) v2's `omitempty` does NOT omit `false` bools or `0` ints (breaking change from v1) — use `omitzero` instead (see `daghtml/types.go` `Error bool`); (3) indentation/escaping are options at construction time (`jsontext.WithIndent("  ")`, `jsontext.EscapeForHTML(true)`) — there are NO `SetIndent`/`SetEscapeHTML` methods; (4) `json.MarshalEncode(encoder, v)` via `jsontext.Encoder` adds a `\n` after each top-level value (same as v1's `Encoder.Encode`), so `JSONLWriter.Encode` does not add a manual newline; (5) `json.Marshal` has variadic `opts` and is NOT directly assignable to `func(any)([]byte,error)` — wrap in a closure.
- **Error system design (three-tier model)**: The error contract follows Go convention with three complementary layers: (1) **Sentinel errors** (`var ErrFoo = errors.New(...)`) for matchable conditions consumers check via `errors.Is` — root exports `ErrColumnMismatch` and `ErrNilRow` for validation failures; sub-modules export domain-specific sentinels (nom: `ErrCycleDetected`). (2) **Typed error structs** (`*InvalidShapeError`, `*InvalidColorModeError`, `*InvalidFormatError`, `*InvalidLineStyleError`, `*InvalidNodeShapeError`, `*UnsupportedFormatError` in root; `*InvalidRankDirError`, `*InvalidSplineStyleError` in graph; `*InvalidActivityStatusError`, `*InvalidActivityKindError` in nom; `*InvalidDirectionError`, `*InvalidNodeShapeError`, `*InvalidArrowTypeError`, `*InvalidConstraintError`, `*InvalidTextTransformError` in d2) for structured errors consumers extract via Go 1.26's `errors.AsType[*T](err)` and read fields like `Value` and `Allowed`. Every typed error follows the canonical shape: `Value string` + `Allowed []T` (when applicable), with an `Error()` method that includes the allowed-values list dynamically (never hardcoded as string literals). All `All<Type>s` variables are exported (`AllShapes`, `AllColorModes`, `AllFormats`, `AllLineStyles`, `AllNodeShapes`, `AllRankDirs`, `AllSplineStyles`) and used to populate `Allowed` at construction time. The nil-`Allowed` guard (`if len(e.Allowed) == 0`) ensures minimal errors render cleanly without the `(allowed: )` suffix. (3) **Wrapping** via `fmt.Errorf("context: %w", err)` — every `fmt.Errorf` in the codebase uses `%w`. See `docs/ERROR_SYSTEM.md` for the full consumer reference and `docs/adr/0013-error-system-design.md` for the ADR. `*ParseError` (from `ParseEnum`) is exported but internal in practice — domain-specific `Parse*` functions discard it and return their own richer typed errors. The invariant: root owns the error contract; sub-modules wrap, never redefine root's sentinels. Never make functions return concrete types instead of `error`. Never dump render output (`out=%v`) into error messages — it's the failed result, always garbage on the error path.
- **Escaping is centralized in `escape/`, render-time only (v0.38 review)**: `escape.MarkdownCell` (pipe/newline/backslash), `escape.PlantUMLID` (allowlist + `fallbackID` "node"), `escape.MermaidText` (HTML-escape + `mermaidEntityGuard` for `#xx;` entity smuggling), `dotGraphID` in graph/ (`%q` when not plain alphanumeric). Never hand-roll per-renderer escaping or pre-escape data before it reaches a renderer. Empty sanitized IDs fall back to `fallbackID`, never an empty string.
- **nom layered mode sorts by `Status.Interest()` (v0.38 review)**: `sortNodesByPriority` in tree_render_layered.go shares the tree-mode Interest ordering (failed > running > pending > completed). Never re-introduce a per-mode priority ladder — the inverted-ladder bug (failed sinking below pending) came from exactly that.
- **`ActivityCounts` has an `Other` bucket (v0.38 review)**: custom statuses registered via `RegisterStatus` count into `Other`, not into the void. If you add a mutation path to `ns.activities`, `adjustStatusCount`'s default case must keep routing unknown statuses to `Other` — `TestActivityCountsCache_LifecycleConsistency` verifies the cache against a brute-force recount.
- **TUI layout is pinned by test (v0.38 review)**: `TestNOMStyle_TreeStartLineMatchesRenderedLayout` asserts the line at `treeStartLine` IS the first rendered tree row (with and without a message line). Any chrome change above the tree must keep `nomTreeStartLine()` and the rendered layout in sync — the mouse-click mapping depends on it (the old hardcoded `chromeLinesAboveTree=5` selected the wrong node for months).
- **Integration test helpers take `*testing.T` (v0.38 review)**: `render*Format`/markdown/event helpers in integration/ fatal at the source (`mustRender`), never swallow render/setup errors — a swallowed error turns content assertions into misleading "missing X" failures or vacuous passes. The reporter's Report* surface is smoke-tested ONLY inside tui/ (package-internal `newTestReporter` suppresses program startup); every Report* call from outside tui starts a REAL tea.Program writing to stdout.
- **"Tests encode the bug" is the house trap**: 6 confirmed instances this review (table footer index, tui click formula, nom counts recount helper, PlantUML golden, buildStyleFunc footerRowIndex assertions, XML vacuous `&&` guard). When a test derives expectations from the same constant/formula/field as the implementation, it verifies nothing — probe actual rendered output (render → split lines → assert content) before writing or trusting the assertion.

## Gotchas

Things that will silently break or that an agent would get wrong from code alone.

- **`GOEXPERIMENT=jsonv2` is required** — All `encoding/json/v2` and `encoding/json/jsontext` imports need this env var. The flake apps (`nix run .#build`, `nix run .#test`, `nix run .#lint`, etc.) and devShells auto-set it. Running bare `go build`/`go test` fails with "build constraints exclude all Go files" — set it: `GOEXPERIMENT=jsonv2 go test ./...`.
- **v2 `omitempty` does NOT omit `false`/`0`** — In `encoding/json/v2`, `omitempty` only omits empty strings, nil pointers, empty slices/maps. It does NOT omit `false` bools or `0` ints (breaking change from v1). Use `omitzero` instead.
- **Never import a sub-module into root** — see Core Invariant above.
- **Pattern B: sibling deps pin the released version + `replace`** — after `d16650b` (2026-08-07) all sibling requires use real versions (currently `v0.37.0`) plus committed `replace` directives. Do NOT revert pins to the `v0.0.0` sentinel (that model is dead) and do NOT delete the `replace` directives. On each release, bump every sibling pin. `daghtml` and `escape` are zero/low-dep like `testhelpers` and independently publishable.
- **Releases need 17 tags, not 1** — cutting only the root `vX.Y.Z` tag without the 16 submodule tags (`<module>/vX.Y.Z`) has happened TWICE (v0.36.0, v0.37.0). Always use `scripts/tag-release.sh` or verify via `scripts/pre-tag-check.sh` (which now checks parity). The `release.yml` auto-tagging step is the systemic backstop. See `docs/RELEASE_CHECKLIST.md`.
- **`testhelpers/` is the ONLY independently versioned sub-module** — it has real published tags. All other sub-modules use v0.0.0 + replace.
- **`testhelpers/` is zero-dep by design** — it cannot import `output`. Cross-module test helpers must stay local to each module or use table-driven patterns.
- **`internal/` is root-only (if added)** — Go forbids sub-modules from importing `internal/` packages, so any `internal/` package in root cannot be shared with sub-modules. Currently root has no `internal/` dir; sub-modules inline their own test helpers (shared zero-dep helpers live in the `testhelpers/` module).
- **Depguard restricts imports** — `.golangci.yml` has explicit allow-lists. When a module gains a new sibling dep, add it to BOTH the `default` and `main` allow-lists or lint fails. Each module has its own `.golangci.yml` section.
- **Every module's `go.mod` needs `replace` directives** for sibling deps, plus add the module to `flake.nix`'s `modules` list and `go.work.example`'s `use (...)` block.
- **Root test files must NOT import sub-modules** — root's `go.mod` must stay clean (only external deps + `testhelpers`). Cross-module tests belong in `integration/`. This is enforced by the Pattern B model: sub-module deps at v0.0.0 would break external consumers.
- **NOM events are typed structs** (e.g., `nom.WorkflowStarted{ID: ...}`, `nom.ActivityCompleted{ID: ...}`, `nom.ActivityProgress{...}`, `nom.ActivityRetrying{Attempt: 1, Reason: "timeout"}`), constructed directly. The `Event` interface is sealed (unexported `isEvent()` marker). The `Event*` string constants (`EventWorkflowStarted`, `EventActivityProgress`, etc.) are kept only as stable logging/metrics identifiers — never re-introduce string-based event dispatch or `GetEventType()`.
- **CI/NO_COLOR detection is in root** — `output.IsCI()` and `output.IsNoColor()` (file: `envdetect.go`). Sub-modules call `output.IsCI()`. Don't re-inline or re-create a separate envdetect module.
- **Code duplication gates**: `art-dupl -t 4` is the production gate; `art-dupl --sort total-tokens -t 1 --type-aware` is the strict audit. The July 2026 sweep reached zero t=4 groups and 24 accepted strict groups. These are minimum idioms: functional options, lock scopes, short error handling, module-boundary interfaces/type re-exports, test scaffolding, and self-contained examples. See ADR 005 and ADR 008.
- **BuildFlow pre-commit hook deletes `CODE_OF_CONDUCT.md`** — the hook (`buildflow --build-mode pre-commit --staged-only`) has a check that considers CoC redundant with CONTRIBUTING.md and auto-deletes it, then re-stages the deletion. Always use `git commit --no-verify` OR verify `CODE_OF_CONDUCT.md` is intact after every non-`--no-verify` commit. This is a BuildFlow config issue, not fixable in-repo.
- **Diagram escaping is render-time, not input-time** — All diagram formats (D2, DOT, Mermaid, PlantUML) escape user input at render time via the `escape/` module. Never pre-escape data before passing it to a renderer. Style values (Fill, Stroke, FontColor) are also escaped — this was a vulnerability that was fixed in v0.18+. If adding new style attributes to any diagram renderer, always apply the corresponding `escape.*()` function.
- **teatest/v2 vs teatest/v1** — The TUI uses `charm.land/bubbletea/v2` which requires `github.com/charmbracelet/x/exp/teatest/v2` (NOT `github.com/charmbracelet/x/exp/teatest` — the v1 package imports `github.com/charmbracelet/bubbletea` which is a DIFFERENT module with incompatible types). The v2 `tea.Model` interface has `View() tea.View`, not `View() string`. Key messages use `tea.KeyPressMsg{Code: 'q'}` not v1's `tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune{'q'}}`.
- **VT and teatest deps are external, not sibling** — `github.com/charmbracelet/x/vt` (in `nom/`) and `github.com/charmbracelet/x/exp/teatest/v2` (in `tui/`) are regular external dependencies, NOT Pattern B sibling modules. They use real version pins, not v0.0.0 + replace. Add them to the module's `.golangci.yml` allow-list if depguard complains.
- **erraudit `context_loss`, `generic_return`, and `stdlib_constructor` are false positives for this project** — `erraudit` flags three patterns that are intentional Go conventions here: (1) `context_loss` suggests adding `out=%v` to error messages, but `out` is the failed render result (always garbage on the error path); (2) `generic_return` suggests returning concrete error types instead of `error`, but Go convention is to return `error` and let callers match via `errors.Is`/`AsType`; (3) `stdlib_constructor` (triggered ONLY by the opt-in `--enforce-go-error-family` flag) suggests replacing `fmt.Errorf`/`errors.New` with `errorfamily.NewRejection`, but `go-error-family` was formally evaluated and rejected (`docs/research/go-error-family-adoption-report.html`, verdict "Do Not Adopt") — the project deliberately uses standard Go error patterns (sentinels + typed structs + `%w` wrapping per ADR 013) and adding a new dependency to the dependency-light root would violate the Core Invariant. The only real erraudit finding was `shape.go:107` (silently ignored error — now documented as intentional). Do NOT zero these findings by following the tool's suggestions; they would degrade the error system. See ADR 013.
